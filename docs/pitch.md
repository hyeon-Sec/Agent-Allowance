# 발표와 데모 가이드

## 30초 소개

“AI에게 결제를 맡기면서도 지출 권한은 직접 관리할 수 있을까요? Agent Allowance는 사용자가 정한 예산을 Sui 객체에 넣습니다. AI가 상점을 찾고 결제하지만, 허용 수신자·한도·정지는 체인이 검사합니다. 소유자는 자신의 지갑으로 정책을 바꾸고, 앱은 결제 전에 결정 기록을 Walrus에 저장하고 읽어 확인합니다. 이후 대화에서는 그 기록을 다시 참고합니다.”

## 2~3분 데모

1. 정책 화면: 예산 0.3 SUI, 1회 0.1, 24시간 주기 0.2. 주기형 한도라고 설명합니다.
2. “점심 정식 사줘”: 승인 결과에서 Sui 이벤트와 Walrus 기록을 엽니다.
3. “지난번 무엇을 샀는지 알려줘. 새 결제는 하지 마”: 기록 조회 도구와 과거 결제 설명을 보여줍니다.
4. 공격 시뮬레이션: LLM을 거치지 않고 공격자 주소나 한도 초과 금액으로 호출합니다. `SpendBlocked`와 잔액을 확인합니다.
5. 소유자 지갑으로 정지: 지갑에서 서명하고 다시 공격 시뮬레이션을 실행해 정지 사유를 확인합니다.
6. 실행 오류와 결과 미확인은 정책 차단과 별도로 표시한다는 점을 설명합니다.

채팅은 API 키와 모델 사용 권한이 필요합니다. 모델이 한도 초과를 미리 알아채면 결제를 시도하지 않을 수 있으므로 체인 차단은 공격 버튼으로 보여주세요. 반복 시연 시 잔액·가스·현재 정책을 먼저 확인하세요.

## 예상 질문

- **서버가 소유자 키를 가지고 있나요?** 런타임은 소유자 키 설정을 거절하고 소유자 서명 API도 없습니다. 브라우저 지갑이 직접 서명합니다. 초기 생성 스크립트는 소유자 환경에서 별도로 실행합니다.
- **기록이 영구적인가요?** 정해진 epochs 동안 보관하며 연장이 필요합니다. 현재 자동 연장·암호화는 없습니다.
- **실제 사고 과정을 증명하나요?** 에이전트가 제출한 요청·결정 이유를 보관합니다. 그것이 실제 내부 판단의 진실성을 증명하지는 않습니다.
- **탈취 키도 기록을 꼭 남기나요?** 앱은 기록 확인 후 송금하지만 계약은 임의의 blob ID를 허용합니다. 체인의 지출 제한과 앱의 기록 정책을 구분합니다.
- **모든 공격이 기록되나요?** 성공한 트랜잭션에 들어 있는 차단 이벤트를 확인할 수 있습니다. 전체 트랜잭션이 abort하면 이벤트도 롤백됩니다.
- **무엇을 기억하나요?** 로컬 결제 목록으로 같은 Allowance의 최근 기록을 찾아 Walrus에서 읽습니다. 장기 인덱싱이나 MemWal은 아직 사용하지 않습니다.
- **어떤 피해를 막나요?** Allowance의 정책 밖 지출을 차단합니다. 허용 상점으로의 악성 결제, 주기 경계 지출, 에이전트 가스 키의 자금까지 모두 보호하지는 않습니다.
